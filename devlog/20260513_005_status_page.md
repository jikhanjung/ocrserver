# 20260513_005 — 서비스 상태 페이지 추가

## 작업 내용

### 추가된 엔드포인트

| Method | Path | 설명 |
|---|---|---|
| `GET` | `/status` | 서비스 상태 웹 페이지 |
| `GET` | `/api/services` | 서비스 헬스체크 JSON API |

### /api/services 응답 예시

```json
{
  "chandra": {"status": "ok", "http_status": 200},
  "llm":     {"status": "ok", "http_status": 200},
  "_meta": {
    "chandra_url": "http://nginx:80/health",
    "llm_url": "http://nginx:80/llm/health",
    "concurrency": 6,
    "uptime_s": 165
  }
}
```

`status` 값: `ok` / `error` (비정상 HTTP 코드) / `down` (연결 실패)

### /status 페이지 구성

- Chandra OCR / Qwen3-14B LLM 각각 상태 카드 (정상 = 초록, 오류 = 빨강)
- Wrapper 시스템 메트릭: 가동시간, 동시성, 총 Job 수, 처리 중 Job 수
- 빠른 테스트 버튼: `/health`, `/llm/health`, `/llm/v1/models` 를 브라우저에서 직접 확인
- 10초 자동 갱신
- 대시보드 navbar에 "서비스 상태" 링크 추가

### 트러블슈팅

**nginx 라우팅 누락**: `/status` 요청이 catch-all `location /` 블록에 걸려 chandra로
라우팅됨 → 404. `location = /status` 추가로 해결.

**Docker bind mount inode 문제**: `nginx.conf` 파일을 in-place 편집 후 `nginx -s reload`
해도 컨테이너 내부 파일이 갱신되지 않음. `docker compose restart nginx`로 해결.
(일부 에디터가 파일 교체 방식으로 저장 시 inode가 바뀌고, Docker `:ro` 마운트가
구 inode를 참조하는 현상)
