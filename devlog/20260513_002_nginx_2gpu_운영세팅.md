# 2026-05-13 — nginx 리버스프록시 + 2-GPU 운영 환경 구성

다른 서버에서 빌드한 `honestjung/ocrserver:latest` 이미지가 로컬에 준비된 상태에서, nginx 로드밸런서 + chandra-a/b 컨테이너 2개를 `/srv/ocrserver`에 운영 환경으로 세팅하고 외부 접근까지 검증.

## 환경

- 호스트: jikhanserver (172.16.112.150)
- GPU: Quadro RTX 8000 × 2 (device 0, 1)
- 이미지: `honestjung/ocrserver:latest` (50.8GB, 다른 서버에서 빌드 후 이미 로컬에 존재)

## 작업 내용

### 1. docker-compose + nginx 세팅 확정

`docker-compose.local.yml`에 healthcheck 추가. 기존 단순 `depends_on` → `condition: service_healthy`로 변경하여, chandra-a/b 가 `/health` 200 응답을 줄 때까지 nginx가 기동을 대기하도록 구성.

healthcheck 설정:
- `start_period: 180s` (vLLM 모델 로드 대기)
- `interval: 30s`, `retries: 20`

nginx.conf: `least_conn` upstream, `client_max_body_size 32m`, `proxy_read_timeout 300s` (OCR 응답 대기).

### 2. /srv/ocrserver 운영 디렉토리 구성

프로젝트 repo(`~/projects/ocrserver`)와 별도로 `/srv/ocrserver`를 운영 디렉토리로 분리. 구성:

```
/srv/ocrserver/
├── docker-compose.yml   # 운영용 (프로젝트의 docker-compose.local.yml 기반)
├── nginx.conf
├── start.sh             # docker compose up -d
├── stop.sh              # docker compose down
├── pdfs/                # OCR 입력 (컨테이너에 read-only 마운트)
└── ocr_json/            # OCR 출력 결과
```

`/srv` 는 root 소유라 `mkdir`/`chown`은 별도 셸에서 sudo로 실행.

### 3. systemd 서비스 등록

`/etc/systemd/system/ocrserver.service` 생성, `systemctl enable` 완료 → 부팅 시 자동 기동.

```ini
[Unit]
After=docker.service
Requires=docker.service

[Service]
Type=oneshot
RemainAfterExit=yes
WorkingDirectory=/srv/ocrserver
ExecStart=/usr/bin/docker compose up -d
ExecStop=/usr/bin/docker compose down
TimeoutStartSec=300
```

### 4. systemd 타임아웃 문제 해결

**증상**: `systemctl start ocrserver` 실행 시 5분 후 timeout으로 실패.

```
ocrserver.service: start operation timed out. Terminating.
ocrserver.service: Failed with result 'timeout'.
```

**원인**: `depends_on: condition: service_healthy`가 있으면 `docker compose up -d`(`-d` 옵션이어도)가 nginx가 healthy 상태가 될 때까지 블로킹 대기함. vLLM 로드 시간(2~3분) + healthcheck 대기가 `TimeoutStartSec=300`을 초과.

`--no-wait` 플래그를 먼저 시도했으나 Docker Compose v5.1.3에서 미지원.

**해결**: `/srv/ocrserver/docker-compose.yml`에서 nginx의 `depends_on`을 단순 컨테이너 시작 대기로 변경.

```yaml
# 변경 전
depends_on:
  chandra-a:
    condition: service_healthy
  chandra-b:
    condition: service_healthy

# 변경 후
depends_on:
  - chandra-a
  - chandra-b
```

`docker compose up -d`가 즉시 리턴. nginx는 vLLM 준비 전 약 2~3분간 502를 반환하다가 정상화. chandra 컨테이너의 healthcheck는 모니터링용으로 유지.

## 최종 검증

```
docker compose -f /srv/ocrserver/docker-compose.yml ps

NAME                    STATUS
ocrserver-chandra-a-1   Up (healthy)
ocrserver-chandra-b-1   Up (healthy)
ocrserver-nginx-1       Up   0.0.0.0:8080->80/tcp

curl http://172.16.112.150:8080/health       → 200 OK (body 없음, vLLM 정상)
curl http://172.16.112.150:8080/v1/models    → {"data":[{"id":"chandra",...}]}
```

포트 8080이 `0.0.0.0`에 바인딩, ufw 비활성 → 내부망 어디서나 접근 가능.

systemd `enabled` + `active (exited)` 상태 정상 확인.

## 메모

- `docker compose -f /srv/ocrserver/docker-compose.yml ps` 로 healthy 상태 확인. `-C` 플래그는 이 버전에서 미지원.
- `/health` 는 200 + 빈 body가 정상 (vLLM FastAPI 스펙). 브라우저에서 빈 화면으로 보이는 게 맞음.
