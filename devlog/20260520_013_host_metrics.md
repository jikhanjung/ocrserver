# 20260520_013 — 호스트 메트릭 수집 + /metrics 페이지

## 작업 내용

1분 단위로 서버 부하·GPU 상태·OCR 처리량을 SQLite에 적재하고 웹에서
그래프로 조회할 수 있게 추가.

### 새 컴포넌트

| 파일 | 역할 |
|---|---|
| `scripts/metrics_collector.py` | 한 번 실행될 때마다 한 행 INSERT (호스트 메트릭 + GPU) |
| `scripts/systemd/ocrserver-metrics.{service,timer}` | 1분 주기 트리거 |
| `wrapper/main.py` `/api/metrics` | 버킷 집계 + jobs/min 조인 |
| `wrapper/metrics.html` `/metrics` | Chart.js 시계열 6종 |

### 데이터 흐름

```
[ host ]                           [ wrapper container ]
nvidia-smi ─┐
/proc/* ────┼─→ metrics_collector.py ─→ /srv/ocrserver/data/metrics.db
                  (systemd timer, 1m)        │ (= /data/metrics.db)
                                             ↓
                                       GET /api/metrics
                                             ↓
                                       /metrics (Chart.js)
```

수집기는 호스트의 systemd timer에서 root로 실행. `/srv/ocrserver/data/`는
wrapper 컨테이너의 `/data` 마운트와 같은 경로 — 컨테이너는 read-only로 연다.

### 스키마

```sql
CREATE TABLE metrics (
    ts INTEGER PRIMARY KEY,
    load1, load5, load15 REAL,
    mem_used_mb, mem_total_mb INTEGER,
    gpu0_util, gpu0_temp REAL,
    gpu0_mem_used_mb, gpu0_mem_total_mb INTEGER,
    gpu1_util, gpu1_temp REAL,
    gpu1_mem_used_mb, gpu1_mem_total_mb INTEGER
);
```

`INSERT OR REPLACE` 이므로 같은 초에 두 번 실행돼도 안전. 보존 기간은
무제한 — 1분 해상도라 1년이 약 52만 행, SQLite WAL로 충분.

### 다운샘플링

API는 `?range=` (5m/15m/30m/1h/3h/6h/12h/24h/7d/30d/all)을 받아
대략 360 포인트가 되도록 `step`을 자동 결정 (60/120/300/.../86400s
사다리). 버킷별 `AVG()` 집계. jobs/step은 `ocrserver.db`의 `completed_at`
완료 행을 따로 카운트해 동일 그리드에 정렬.

### 설치

```bash
# 호스트에서 (root)
sudo install -m 0755 /home/jikhanjung/projects/ocrserver/scripts/metrics_collector.py \
    /srv/ocrserver/scripts/metrics_collector.py
sudo install -m 0644 /home/jikhanjung/projects/ocrserver/scripts/systemd/ocrserver-metrics.service \
    /etc/systemd/system/
sudo install -m 0644 /home/jikhanjung/projects/ocrserver/scripts/systemd/ocrserver-metrics.timer \
    /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now ocrserver-metrics.timer

# 수동 한 번 실행해 DB 생성 확인
sudo /usr/bin/python3 /srv/ocrserver/scripts/metrics_collector.py --print

# wrapper 컨테이너 재시작 (새 라우트/HTML 반영)
cd /srv/ocrserver && docker compose build wrapper && docker compose up -d wrapper nginx
```

`docker compose build wrapper`가 필요한 이유: `metrics.html`이 이미지 안에
COPY로 들어가야 함 (`wrapper/Dockerfile`). nginx도 재시작해야 새 `location =
/metrics` 블록이 적용됨.

### 트러블슈팅

**`range`는 파이썬 빌트인을 가린다**: FastAPI 쿼리 파라미터 이름을 `range`로
지으면 함수 안에서 `list(range(...))` 호출이 `'str' object is not callable`
로 터짐. URL은 `?range=`로 유지하되 파이썬 인자는 `range_: str = Query(...,
alias="range")`로 분리.

**스테일 uvicorn**: 포트 충돌로 새 프로세스가 즉시 죽고 옛 코드가 계속 응답하는
케이스가 있었음. `fuser -k <port>/tcp`로 확실히 정리 후 재기동.

**nginx conf 가 dev tree와 `/srv/ocrserver/`로 이원화돼 있음**: 새 `location =
/metrics` 블록을 `nginx.ocr.conf`/`nginx.llm.conf`에 추가해도, 배포본은 별도
파일이라 안 반영됨. 증상은 `/metrics` 가 fall-through (`location /`) 로 chandra
업스트림에 가서 vLLM Prometheus 메트릭(`# HELP python_gc_...`)을 토함. 절차:

```bash
cp nginx.ocr.conf nginx.llm.conf /srv/ocrserver/
# 현재 모드의 conf 를 nginx.conf 로도 복사 (mode-*.sh가 평소 하는 일)
cp /srv/ocrserver/nginx.ocr.conf /srv/ocrserver/nginx.conf
cd /srv/ocrserver && docker compose exec nginx nginx -s reload
```

**`docker compose up -d wrapper` 만으로는 컨테이너가 재생성 안 됨**: 이미지
태그(`ocrserver-wrapper:latest`)가 그대로면 compose 가 "Running" 상태로 두고
지나감 — 새 이미지가 안 붙는다. `--force-recreate` 를 붙여야 함:

```bash
cd /srv/ocrserver && docker compose up -d --force-recreate wrapper
```
