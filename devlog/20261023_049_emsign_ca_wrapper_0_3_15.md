# 049 — emSign CA 키 유출 대응, wrapper 0.3.15 (2026-10-23)

## 배경

GHSA-6q48-6c7w-9gw2: emSign ECC Root CA - G3 아래 중간 CA 키 8개가 유출됐다. 이 루트를 믿는 클라이언트는
외부로 나가는 TLS 를 MITM 당할 수 있다. 고친 버전은 certifi ≥ 2026.10.19, pip ≥ 26.2.2(pip 은 내장 certifi 를 쓴다),
uv ≥ 0.13.4 다. banjang 세션의 요청으로 이 호스트를 점검했다.

## 점검 결과 (10-22/23)

- 호스트 OS 저장소(ca-certificates 20260816ubuntu0.26.04.1)에는 G3 가 없다. 시스템 python3 의 certifi 는 Debian 패치로 OS 저장소를 쓴다.
- 컨테이너 `wrapper`·`llmwrapper`(python:3.11-slim, Debian 13.7):
  - certifi 2026.07.22, pip 24.0(내장 certifi 2023.07.22);
  - ca-certificates 20250419 라 G3 가 있었다.
- `nginx:alpine` 에도 G3 가 있었다.

## 조치

- 호스트:
  - 쉬는 venv 9개와 uv cpython 3.10/3.12 를 pip 26.2.2 로 올렸다.
  - certifi 가 깔린 venv 4개는 certifi 2026.10.19 로 올렸다.
  - uv(`~/venv/fsis2026`)는 0.13.5 로 올렸다.
  - 도판 워커가 쓰는 `~/venv/ocrserver` 와 figsplit 학습 venv 는 건드리지 않았다(HANDOFF 「곧 해야 할 작업」).
- `wrapper/Dockerfile`:
  - `ca-certificates` 를 올리고, `/etc/ca-certificates.conf` 에서 G3 를 `!` 로 빼고 `update-ca-certificates --fresh` 를 돌린다.
    Debian 의 20250419+deb13u1 은 이미 G3 를 뺐다. sed 는 그 줄이 남아 있는 베이스를 대비한 것이다.
  - `pip install -U "pip>=26.2.2" "certifi>=2026.10.19"` 를 먼저 한다. httpx 는 certifi 를 쓴다.
- 배포:
  - `ocrwrapper:0.3.15` 를 `--pull` 로 빌드하고 `--no-deps wrapper llmwrapper` 로 재생성했다.
  - `nginx` 는 새 `nginx:alpine`(1.31.8, G3 없음)으로 재생성했다.
  - 확인: `/healthz` ok 0.3.15, `/status` 200. `/llm/` 502 는 llm 이 정지 중이라 정상이다.
- 0.3.15 는 아직 Docker Hub 에 올리지 않았다(사용자 확인 대기).

## 남은 것

- `~/venv/ocrserver` 의 pip·certifi(워커가 쉴 때, 재시작은 sudo).
- figsplit 학습 venv 의 pip.
- chandra·vllm 이미지는 정지 중이라 보지 않았다.
