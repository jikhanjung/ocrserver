# 2026-05-12 — GPU Docker 환경 구축 및 호스트 네트워크 영구 설정

ocrserver를 RTX 8000 서버에서 컨테이너로 돌리기 위한 사전 세팅 작업. 시작은 단순한 `nvidia-smi` 확인이었으나, 진행 과정에서 KOPRI 내부망 특성과 호스트의 잠재 설정 문제가 연쇄적으로 드러나 모두 정리함.

## 환경

- 호스트: jikhanserver (KOPRI 내부망, 172.16.112.150/21)
- GPU: NVIDIA Quadro RTX 8000 × 2 (드라이버 595.58.03, CUDA 13.2)
- OS: Ubuntu (resolute 코드네임)
- 인터페이스: `enp0s31f6`, 게이트웨이 `172.16.112.1`

## 발견·해결한 문제들

### 1. nvidia-container-toolkit 미설치

`docker run --gpus all` 실행 시 다음 에러:

```
failed to discover GPU vendor from CDI: no known GPU vendor found
```

- `nvidia-ctk` 명령 없음, `/etc/cdi/` 없음, docker runtime에 `nvidia` 미등록
- 즉, GPU 드라이버는 있지만 컨테이너 toolkit이 깔려있지 않음

**해결**: nvidia-container-toolkit 설치 후 docker runtime 등록.

```bash
curl -fsSL https://nvidia.github.io/libnvidia-container/gpgkey \
  | sudo gpg --dearmor -o /usr/share/keyrings/nvidia-container-toolkit-keyring.gpg
curl -s -L https://nvidia.github.io/libnvidia-container/stable/deb/nvidia-container-toolkit.list \
  | sed 's#deb https://#deb [signed-by=/usr/share/keyrings/nvidia-container-toolkit-keyring.gpg] https://#g' \
  | sudo tee /etc/apt/sources.list.d/nvidia-container-toolkit.list
sudo apt-get update && sudo apt-get install -y nvidia-container-toolkit
sudo nvidia-ctk runtime configure --runtime=docker
sudo systemctl restart docker
```

### 2. KOPRI SSL 인터셉트로 인한 HTTPS 검증 실패

위 설치 과정 중 curl/apt가 SSL 검증 실패:

```
curl: (60) SSL certificate ... self-signed certificate in certificate chain
```

`openssl s_client`로 체인 확인 결과 KOPRI 내부망이 모든 HTTPS를 자체 CA(`C=KR, O=KOPRI, CN=KOPRI SSL`)로 재서명하고 있었음. 시스템 신뢰 저장소에는 그 CA가 없는 상태.

**해결**: 체인에서 self-signed 루트를 추출해 시스템 신뢰 저장소에 등록.

```bash
echo | openssl s_client -showcerts -connect nvidia.github.io:443 \
  -servername nvidia.github.io 2>/dev/null | awk '/BEGIN CERTIFICATE/,/END CERTIFICATE/' > /tmp/chain.pem
# self-signed 루트만 골라서 /usr/local/share/ca-certificates/kopri-ssl.crt로 복사
sudo update-ca-certificates
```

이후 curl/apt/pip 모두 정상 동작.

### 3. ICMP 차단 — `ping` 실패의 진짜 원인

KOPRI 망은 ICMP 아웃바운드를 차단함. `ping 8.8.8.8`이 100% 패킷 손실이지만 HTTPS는 정상. 진단 시 `ping`이 아니라 `curl -sI`로 확인해야 함.

### 4. systemd-resolved 업스트림 DNS 누락

`docker run --gpus all` 실행 후 호스트의 HTTPS가 즉시 실패하는 증상 (`http_code=000`, `time=0.001s`). 처음엔 docker가 호스트 네트워크를 깨뜨린다고 의심했으나, 실제 원인은 더 깊은 곳.

**진단 결과:**
- `dig @8.8.8.8`: 응답 OK
- `dig` (시스템 기본): 빈 응답 → 시스템 리졸버(127.0.0.53) 죽음
- `/etc/resolv.conf` → `stub-resolv.conf` 심볼릭 링크
- 이전: stub-resolv.conf 안에 `nameserver 8.8.8.8`이 직접 박혀있었음 (비표준)
- 깨진 후: `nameserver 127.0.0.53`으로 "정상화"됨
- `resolvectl status`: enp0s31f6의 Current Scopes가 `none` — systemd-resolved에 업스트림 DNS가 비어있음

**근본 원인**: KOPRI DHCP가 IP를 안 줘서 누군가 `ip addr`로 정적 IP만 잡아두었고, DNS는 systemd-resolved에 설정 없이 stub-resolv.conf를 수동으로 8.8.8.8로 덮어쓴 임시방편 상태였음. docker 또는 systemd-resolved의 주기적 동작으로 stub-resolv.conf가 재생성되면서 임시방편이 날아간 것.

**1차 해결 (글로벌 fallback)**:

```bash
sudo tee /etc/systemd/resolved.conf.d/dns.conf <<'EOF'
[Resolve]
DNS=8.8.8.8 8.8.4.4
FallbackDNS=1.1.1.1
EOF
sudo systemctl restart systemd-resolved
```

### 5. 정적 IP를 netplan에 영구 등록

`ip addr add`로 한 IP 설정은 재부팅 시 사라짐. 기존 `00-installer-config.yaml`은 DHCP 기반이었으므로 정적 설정으로 교체.

```yaml
network:
  version: 2
  ethernets:
    enp0s31f6:
      dhcp4: false
      dhcp6: false
      match:
        macaddress: e0:d5:5e:23:d5:d9
      set-name: enp0s31f6
      addresses:
        - 172.16.112.150/21
      routes:
        - to: default
          via: 172.16.112.1
      nameservers:
        addresses:
          - 8.8.8.8
          - 8.8.4.4
```

`sudo netplan try`로 안전하게 적용 (120초 내 미확정 시 자동 롤백). 검증 후 확정.

`gateway4:`는 deprecated되어 `routes:` 블록 사용. systemd-networkd가 renderer (NetworkManager는 비활성).

## 최종 검증

```
docker run --rm --gpus all nvidia/cuda:13.0.0-base-ubuntu22.04 nvidia-smi
# → Quadro RTX 8000 × 2 정상 인식

curl -sI -o /dev/null -w "after_docker=%{http_code}\n" https://nvidia.github.io/
# → after_docker=404 (정상 HTTPS 응답, 페이지만 없음)
```

Docker 사이클 전/후로 호스트 외부 연결 모두 멀쩡. 재부팅 후에도 IP·DNS·CA 모두 영구 유지.

## 남은 메모

- **컨테이너에 KOPRI CA 주입 필요**: nvidia developer repo처럼 SSL 검증이 필요한 외부 호출을 컨테이너 내부에서 하려면 빌드 시 `COPY kopri-ssl.crt /usr/local/share/ca-certificates/ && update-ca-certificates`를 Dockerfile에 추가하거나 런타임 bind-mount 필요. `nvidia/cuda:*-base` 같은 minimal 이미지에는 `ca-certificates` 패키지부터 깔아야 함.
- **연결 진단 시 `ping` 금지** — KOPRI ICMP 차단으로 항상 실패하므로 무의미. `curl -sI`로 확인.
- **DNS 이중 안전망**: netplan(인터페이스별)과 resolved.conf.d(글로벌 fallback) 양쪽에 DNS가 들어가 있음. 의도된 중복.
